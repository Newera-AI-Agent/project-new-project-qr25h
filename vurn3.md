# VURN-3: Authentication Bypass via Response Caching on `/image` Endpoint

## Severity
**CRITICAL** - Authentication bypass allowing unauthorized access to AI-generated images

## Affected Endpoint
- `GET /image/{prompt}` - Image generation endpoint

## Description
The `/image` endpoint serves cached image responses without validating authentication. After a legitimate authenticated request is made for a specific prompt, subsequent unauthenticated requests for the same prompt return the cached image with HTTP 200, completely bypassing API key authentication.

## Impact
- **Unauthorized access to AI-generated images** - Any user can retrieve images generated by other users' API keys
- **Data leakage** - Sensitive prompts and their generated images become accessible without authentication
- **API key abuse** - Attackers can consume paid image model responses without valid credentials
- **Content exposure** - Potentially sensitive/private generated images exposed
- **Rate limit bypass** - Cached responses don't count against rate limits
- **Cost impact** - Image generation typically costs more than text generation

## Root Cause
The caching layer (likely Cloudflare Cache or similar CDN) caches responses based on the URL path (`/image/{prompt}`) without considering the `Authorization` header as a cache key variant. This means:
1. User A makes authenticated request: `GET /image/Secret%20prompt` with valid API key → Returns image, caches it
2. User B makes unauthenticated request: `GET /image/Secret%20prompt` → Returns cached image (HTTP 200)

## Proof of Concept

### Step 1: Make authenticated request (primes cache)
```bash
curl -H "Authorization: Bearer sk_6yihP7AvWpCFJt8dvQrzEMXKvLLbwaxl" \
  "https://gen.pollinations.ai/image/Unique%20test%20image%20prompt%20VURN3%2012345" \
  -o image1.png
```
**Result:** HTTP 200 - Returns generated image

### Step 2: Make unauthenticated request (bypasses auth)
```bash
curl "https://gen.pollinations.ai/image/Unique%20test%20image%20prompt%20VURN3%2012345" \
  -o image2.png
```
**Result:** HTTP 200 - Returns SAME cached image WITHOUT authentication

## Evidence
- Tested against production endpoint `https://gen.pollinations.ai`
- Test API key: `sk_6yihP7AvWpCFJt8dvQrzEMXKvLLbwaxl` (2 pollen balance)
- Multiple unique prompts tested - all showed cache bypass
- Images are served from cache (CF-Cache-Status: HIT on second request)
- Cache persists for several minutes
- Works with various image models (gptimage, flux, etc.)

## Affected Code Locations
Based on codebase analysis:
- **Cache configuration** - Likely in Cloudflare Workers/Pages configuration or CDN settings
- **Endpoint handler** - `pollinations-repo/gen.pollinations.ai/src/routes/image.ts` (or similar)
- **Authentication middleware** - `pollinations-repo/gen.pollinations.ai/src/middleware/auth.ts` - `requireUser` not enforced on cached responses
- **Model permissions** - `pollinations-repo/shared/registry/model-permissions.ts` - `keyAllowsModel` check bypassed by cache

## Solution / Remediation

### Immediate Fix (Configuration)
1. **Add `Authorization` header to cache key** - Configure CDN to vary cache by `Authorization` header
2. **Add `Cache-Control: private, no-store`** for authenticated endpoints
3. **Use `Vary: Authorization`** header on all authenticated responses

### Code-Level Fix
```typescript
// In image endpoint handler - ensure auth check runs BEFORE cache lookup
export const imageHandler = async (c: Context) => {
  // 1. Validate authentication FIRST
  const auth = await requireUser(c); // This must execute before any cache check
  
  // 2. Validate model access for image models
  const modelAccess = await requireModelAccess(c);
  
  // 3. Check balance/budget (images cost more)
  await checkBalance(c);
  
  // 4. Only then process request
  const prompt = c.req.param('prompt');
  // ... rest of handler
};
```

### Cache Configuration (Cloudflare)
```javascript
// In Cloudflare Workers/Pages config
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    
    // For image endpoint, include Authorization in cache key
    if (url.pathname.startsWith('/image/')) {
      const cacheKey = new Request(request.url, {
        headers: {
          'Authorization': request.headers.get('Authorization') || ''
        }
      });
      // ... cache logic with modified key
    }
    // ... rest of cache logic
  }
}
```

### Alternative: Disable Caching for Authenticated Endpoints
```javascript
// Simplest fix - don't cache authenticated endpoints at all
const isAuthenticatedEndpoint = 
  url.pathname.startsWith('/text/') ||
  url.pathname.startsWith('/image/') ||
  url.pathname.startsWith('/v1/chat/completions');

if (isAuthenticatedEndpoint) {
  // Bypass cache entirely
  return fetch(request);
}
```

3. Different API key for same prompt → HTTP 401 or new image (not cached)
4. Same API key, different prompt → New image generated
